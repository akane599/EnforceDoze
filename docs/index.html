Independent controls, explicit tradeoffs

Doze and schedules

Configure a screen-off delay and local-time periods, including overnight. Charging and detected calls can pause monitoring. Android determines maintenance windows. Exact alarms improve timing; without access, Android may delay triggers.

Sensor access and privacy

SensorService restriction limits app access. Developer sensor privacy is a separate Sensors off control. Both retain originals and read back changes. Neither proves every physical sensor is powered off.

Connectivity and apps

Optional radio, location, battery-saver and app-suspension controls can interrupt delivery. Hotspot and media protections preserve access conservatively when state is unknown. Exemptions cannot compensate for a disabled connection.

Local observations

Inspect up to 200 saved observations with timestamps, screen/idle states, failures and restoration results. Copy, share or clear deliberately. History records coarse battery changes and marks charging or interrupted readings unavailable.

Advanced options

Per-value Doze tunables retain previous values. Tasker automation requires opt-in and a local token. The biometric keyguard setting is experimental and does not establish fingerprint hardware behavior.

Quiet monitoring

The foreground notification stays stable by default. Detailed live status is optional. Access errors and pending recovery use a separate visible notification. Light and dark themes follow your preference.

Access and recovery

Use Shizuku or root for privileged control on Android 16. Legacy ADB-granted app access is limited on modern Android. Permission and command acceptance alone do not establish a feature's outcome.

Recovery records are saved before changes and removed only after the original state is read back. If access is unavailable, changes can remain pending. Reconnect the original access mode and retry. Force-stop blocks background recovery until the app is reopened. Restore before uninstalling or clearing data.

Samsung One UI

Review sleeping and deep-sleeping restrictions for EnforceDoze and Shizuku; use Never sleeping apps where available. Auto Blocker can restrict debugging or installation. Menu names and policy vary. No physical Samsung hardware has been verified for this development build; emulator results do not establish Samsung sensor, modem or biometric behavior.

Build and download

The development workflow builds installable APKs and test reports from GitHub's manual Run workflow control, once approved and published. It does not publish releases or push commits. Review test results and signing information before installing.

Android updates require a compatible signing certificate. Temporary CI keys cannot update the original publisher-signed APK or builds from another run. Stop and restore before uninstalling an incompatible installation.

Permissions with a purpose

  • Phone permission: detect calls and pause automatic Doze.
  • Notifications: show monitoring, errors and pending restoration.
  • Notification access: media-state protection and selected notification filtering.
  • Package visibility: choose installed apps for exemptions and controls.
  • Foreground service, bounded transaction wake locks and optional exact alarms: perform user-enabled monitoring and restoration.
  • Privileged Shizuku/root access: inspect and change supported Android controls. Legacy DUMP and WRITE_SECURE_SETTINGS grants are optional for older modes.
